The '''Sony BRAVIA pre-Android Linux TVs''' are the 2011-2012 generation of Sony BRAVIA flat-panel televisions, which ran a proprietary Linux-based platform before Sony switched the BRAVIA line to Android TV. Hardware ranged from entry models to flagships with 12-bit X-Reality PRO video processing and active (shutter-glasses) 3D. All models included DLNA media playback and an HTML/JavaScript widget platform (AppliCast) served from Sony-operated servers.

==Consumer-impact summary==
The hardware of this generation remains fully functional years after the platform was abandoned &mdash; including 12-bit video processing and active 3D on the higher-end models &mdash; but Sony discontinued every software pillar the sets depend on. Owners are left with smart functionality that no longer works through official channels, no official firmware recovery path for a failed or factory-reset set, GPL-licensed sources that are no longer obtainable from the copyright distributor, and a 3D playback feature that silently fails over DLNA.

Two characteristics distinguish this case from an ordinary end-of-support, and both can be checked against Sony's own servers today. First, the withdrawal is not a matter of files being lost: Sony's AppliCast content servers remain online in 2026 and still return the original application bundles with their original cryptographic signatures. What was switched off is the per-region catalog that tells a television those applications exist &mdash; a single XML file per country.<ref name="cat-eu">{{Cite web |title=AppliCast application catalog for the AZ3 chassis, European region (Catalog_EU_ALL_eng.xml) |url=https://applicast.ga.sony.net/WidgetContents/SNY_WidgetGallery/AZ3/Catalog_EU_ALL_eng.xml |url-status=live |archive-url=https://web.archive.org/web/20260917210301/https://applicast.ga.sony.net/WidgetContents/SNY_WidgetGallery/AZ3/Catalog_EU_ALL_eng.xml |archive-date=2026-09-17
|access-date=2026-09-17 |publisher=Sony Corporation}} Lists eight applications.</ref><ref name="cat-br">{{Cite web |title=AppliCast application catalog for the AZ3 chassis, Brazilian region (Catalog_LA_BRA_por.xml) |url=https://applicast.ga.sony.net/WidgetContents/SNY_WidgetGallery/AZ3/Catalog_LA_BRA_por.xml |url-status=live |archive-url=https://web.archive.org/web/20260917204700/https://applicast.ga.sony.net/WidgetContents/SNY_WidgetGallery/AZ3/Catalog_LA_BRA_por.xml |archive-date=2026-09-17 |access-date=2026-09-17 |publisher=Sony Corporation}} Lists two applications.</ref> Second, several applications never offered in some regions were nonetheless finished and fully localized for those regions, as Sony's own files show.

===3D playback silently broken over DLNA (''2011–present'')===
The 3D-capable models of this line auto-engage 3D from exactly one signal: a ''frame_packing_arrangement'' SEI message (H.264 D.2.4, payload type 45) embedded in the H.264 elementary stream. They ignore the Matroska StereoMode container tag &mdash; the only 3D flag standard rip files carry &mdash; so every DLNA-served 3D video plays flat. The feature was never announced as ending; it fails silently on hardware that displays 3D perfectly from other inputs. The diagnosis was reverse-engineered by an owner and subsequently reviewed and accepted by an independent project: the HandBrake video transcoder merged a patch so that its encoder writes the missing signal, closing a long-standing issue in that project.<ref name="handbrake">{{Cite web |title=libhb: signal stereo 3d frame packing in the x264 encoder (pull request #8100) |url=https://github.com/HandBrake/HandBrake/pull/8100
|access-date=2026-09-18 |date=2026-09-16 |website=GitHub |publisher=HandBrake project}} Independent third-party review and acceptance of the technical finding described in this incident; merged 16 September 2026.</ref> Further reports were filed with the FFmpeg and mpv projects.<ref name="ffmpeg">{{Cite web |title=FFmpeg issue 24530 |url=https://code.ffmpeg.org/FFmpeg/FFmpeg/issues/24530 |access-date=2026-09-18 |publisher=FFmpeg project}} See also {{Cite web |title=FFmpeg issue 24531 |url=https://code.ffmpeg.org/FFmpeg/FFmpeg/issues/24531 |access-date=2026-09-18 |publisher=FFmpeg project}}</ref> No DRM or copy-protection mechanism is involved in the restoration.

The defect is in the signalling chain rather than in any one media server: the same behaviour was subsequently reproduced on the same television through an unrelated server, the UPnP/DLNA server built into Kodi, which serves files byte-for-byte without transcoding. A file whose only stereoscopic signal is the in-stream frame-packing message caused the set to switch to 3D automatically, while the identical file with that message removed &mdash; a difference of 791 bytes, with the picture data untouched &mdash; played flat, and a Matroska file carrying the container-level 3D flag was not listed by the television at all.<ref name="repo" />

===3D display never available to the television's own internet and app content (''2011–present'')===
The 3D processing is a display feature of the panel, documented by Sony as applying to whatever the set shows. The on-device i-Manual describes a 3D button offering three display modes &mdash; Side-by-Side, Over-Under, and ''Simulated 3D'', the last converting ordinary 2D pictures to a simulated-3D effect &mdash; and states that the mode is chosen "to suit the displayed content", with an ''Auto 3D'' setting that engages 3D automatically "when a 3D signal is detected".
<ref name="imanual-3d">Sony Corporation, KDL-46HX855 i-Manual (electronic manual built into the set), "Watching in 3D": document ID W0005741M (English) / W0005743M (Portuguese). Documents the [3D Display] modes Side-by-Side, Over-Under and Simulated 3D, the [Auto 3D] setting that switches automatically when a 3D signal is detected, and the [3D Signal Notification] setting. Not published as a web page; consulted on the television itself.</ref> Crucially, the manual restricts only the two ''stereoscopic'' modes by input signal or format; it places no input, format or source restriction on Simulated 3D, whose only stated caveat is that the effect "may be less pronounced with some picture sources", and it states the one precondition that 3D is available only when pictures are shown full-screen.<ref name="imanual-3d" />

On a set playing video through the platform's own browser/application surface, full-screen, an owner observed that the television detected the 3D signal and said so on screen, raising its own notification &mdash; ''Sinal 3D foi detectado'' ("3D signal detected") &mdash; and then neither switched to 3D automatically nor allowed the manual 3D button to engage it, while the documented 2D-to-3D Simulated 3D mode was likewise unavailable.<ref name="repo" />

The same televisions engage 3D with no user action at all for a stereoscopic photograph read from a USB stick, as the following incident records. The signal detector, the panel and the 3D processing therefore all function, and the television demonstrates as much by announcing the detection to the owner; the only variable is which input the content arrived on. The panel's documented 3D processing has never been reachable from the internet and application content path that Sony built into the set and later shut down.<ref name="repo" />

===3D still photographs: supported from USB, unavailable over the home network (''2011–present'')===
These televisions accept exactly one stereoscopic still-image format, from exactly one input, and refuse every other 3D photograph put in front of them. The format they accept is the Multi-Picture Object (MPO) file written by the 3D cameras Sony and others sold in the same period. Tested by the owner on 19 September 2026 on both televisions, each running its final Brazilian firmware, a correctly written MPO file opened from a USB storage device engages 3D by itself: no prompt, no menu, both views displayed stereoscopically.<ref name="repo" /> That had not previously been established for these models on this firmware, and it demonstrates that the panel, the decoder and the automatic 3D switch all work for photographs.

Everything else the owner tried is a genuine stereoscopic photograph that the television will not display as one. Stereo photographs taken with a 3D mobile telephone of the period are written in the JPS stereo-JPEG format; photographs from the stereoscopic photography community circulate as JPS and as side-by-side JPEG files. On these sets none of those are shown in 3D: where they are listed at all, they are displayed flat, and the 3D button raises a menu offering only the simulated 2D-to-3D conversion, with no side-by-side or over-under option for still images.<ref name="repo" /> The pictures are correctly formed stereo pairs; the television simply does not speak their format, and provides no means of telling it what it is looking at.

The single working combination is therefore narrower than an owner would reasonably infer from how these televisions were sold. A set advertised as a 3D television displays a 3D photograph only if the file is an MPO, only if that MPO is written exactly as the specification requires, and only if it arrives on a USB storage device. Nothing in the marketing, the packaging or the electronic manual states this, and the set offers no message explaining why a stereoscopic photograph it has just listed is being shown flat.

In the Brazilian market these were premium purchases rather than ordinary ones, which is the context in which the limitation matters. The national monthly minimum wage was R$545.00 during 2011 and R$622.00 from 1 January 2012.<ref name="salmin">{{Cite web |title=Decreto nº 7.655, de 23 de dezembro de 2011 |url=http://www.planalto.gov.br/ccivil_03/_ato2011-2014/2011/decreto/d7655.htm |access-date=2026-09-19 |publisher=Presidência da República}} Fixes the national monthly minimum wage at R$622.00 from 1 January 2012, replacing the R$545.00 in force during 2011, under Lei nº 12.382 of 25 February 2011.</ref>
A 46-inch 3D set of this range sold at launch for an amount in the thousands of reais, comparable at the time to the price of a used car and equivalent to many months of minimum-wage income. Launch prices for this market are no longer readily documented online, so this comparison is given as an approximation rather than a figure.

Over the home network, the identical file is flat. Delivered by a media server, byte for byte unaltered, the MPO is shown as an ordinary two-dimensional photograph, and the 3D button raises a menu offering only the simulated 2D-to-3D conversion; no side-by-side or over-under option is offered for still images on that path. Side-by-side stereo photographs, whether full-width or half-width frame-compatible, are flat on both paths.<ref name="repo" />

The reason is the television's own declaration rather than any limit of the panel. A media server asks a television which formats it accepts, and these sets answer with ordinary JPEG photographs in three sizes and nothing else: no MPO of any kind appears in the reply.<ref name="repo" /> The owner tested this directly with a purpose-built media server that offered the same MPO file four different ways. The two copies announced as ordinary JPEG photographs were listed by the television and displayed flat, including the copy whose address ended in the MPO file extension; the two copies announced honestly as MPO files did not appear in the television's browser at all.<ref name="repo" /> The set therefore hides the format it will not admit to accepting, and decodes what remains as a flat photograph, while the same file on a USB stick drives the same panel into 3D without being asked.

No change to any media server can alter this. Two widely used open-source media servers already index and serve MPO files unaltered, and their output is what the television shows flat; a server that described the format correctly instead would have its entries hidden.<ref name="repo" />

Sony's own support material describes this capability inconsistently across regions, and the measurement above settles part of the contradiction.

==Affected models==
Sony distributed software for these televisions '''per chassis generation, not per model''': one catalog and one set of application bundles served every set in a generation, and Sony's own service manuals cover several screen sizes under a single chassis. The incidents above therefore apply to the generation, not only to the models a researcher happened to own.
*'''AZ2-F chassis (2011)''' &mdash; a single Sony service manual covers KDL-32EX725, KDL-40EX725, KDL-46EX725 and KDL-55EX725, with KDL-60EX725 documented separately. 1080p, active 3D, DLNA, AppliCast widgets.
*'''AZ3F chassis (2012)''' &mdash; high-end line of the generation, including KDL-40/46/55HX855 and the HX853 series; 1080p, 12-bit X-Reality PRO processing, active 3D, DLNA, AppliCast widgets.
*'''AZ1 chassis (2010)''' &mdash; the preceding generation, whose catalog is also still served and still answers in 24 languages.<ref name="az1" />
*'''Verified hands-on''' &mdash; KDL-46EX725 (AZ2-F) and KDL-46HX855 (AZ3F).

==Consumer-rights context (Brazil)==
The two sets verified hands-on are Brazilian-market units, and the notices above were published by Sony Brasil. The following provisions of Brazilian consumer law may be relevant to owners in that market. This section states the statute and the matching, sourced facts; it draws no legal conclusion, which is a matter for the Foundation and for Brazilian consumer-law counsel.
*Under the ''Código de Defesa do Consumidor'' (Law 8.078/1990), advertising and product information provided by a supplier are binding and form part of the contract (art. 30). Sony Brasil published consumer material presenting "Internet TV" and "BRAVIA Internet Vídeo" as features of these sets;<ref name="br-promo">Sony Brasil consumer documents "Internet TV" (Sony document W0001861M) and "BRAVIA Internet Vídeo" (W0001142M), presenting the internet-content capability of the BRAVIA line. Not published as web pages; held in the owner's offline document library.</ref> those services were subsequently discontinued per Sony's own notices above.
*The CDC treats defects that render a product unfit for its purpose or diminish its value as ''vícios do produto'' (art. 18), and Brazilian courts have recognised supplier responsibility across a product's ''vida útil'' (useful life), which can extend beyond the formal warranty period.
*The CDC requires manufacturers and importers to ensure the availability of components and technical support while a product is offered and for a reasonable period after production ceases (art. 32).
*The CDC voids abusive contract clauses, including those incompatible with good faith or that place the consumer at exaggerated disadvantage (art. 51) &mdash; relevant where an end-user licence purports to permit unlimited discontinuation of advertised functionality.
*The distinction drawn elsewhere on this page holds here too: the discontinuation of online ''services'' is one question, while the removal of the GPL-licensed ''source code'' Sony's own licence documents point to is a separate obligation arising from the software licences themselves, independent of any service terms.
