'''Sony BRAVIA pre-Android Linux TVs''' are the 2011&ndash;2012 generation of Sony
Bravia flat-panel televisions that ran a proprietary Linux-based platform
(predating Sony's switch to Android TV). Hardware across the line ranged from
entry models to flagship sets with 12-bit X-Reality PRO video processing and
active (shutter-glasses) [[3D television|3D]]. Sony has since discontinued the
platform entirely, removing online services, firmware downloads, and even the
GPL source-code releases required by the licenses of the software the sets run.

== Example hardware ==

* '''KDL-46EX725''' (2011, AZ2-F chassis) &mdash; entry line of the generation
* '''KDL-46HX855''' (2012, AZ3 chassis) &mdash; high-end line of the generation

Both are 46-inch 1080p panels with active 3D, DLNA media playback, and an
HTML/JavaScript widget platform (ApplicaCast) served from Sony-operated
servers.

== What was withdrawn ==

* '''Smart services shut down.''' The widget-server content the platform
  depended on is no longer served; the sets lost their smart functionality.
* '''Firmware downloads removed''' (January 2022). Sony removed the update
  images for these models from its support site, so a set that fails or is
  reset can no longer be brought back to factory firmware through official
  channels.
* '''GPL source downloads deleted.''' The Linux kernel and other GPL-licensed
  component sources Sony was obligated to distribute were removed from
  Sony's own site. The sets still run the binaries, but the corresponding
  source is no longer obtainable from the copyright distributor.
* '''3D playback silently broken over DLNA.''' The sets auto-engage 3D only
  when the H.264 elementary stream carries a ''frame-packing arrangement''
  SEI message (H.264 D.2.4, payload type 45) and ignore the Matroska
  ''StereoMode'' container tag &mdash; the only 3D flag that standard web/rip
  media files carry. The result is that every DLNA-served 3D file plays
  flat on hardware that is fully capable of displaying it. The panels are
  not broken; the signalling the sets were built to read was simply never
  generated by any mainstream media server, and Sony's own 2012 servers
  stopped doing so.

== Owner-developed remediation ==

The owner of the two example sets reverse-engineered the 3D auto-detection
mechanism and restored fully automatic 3D playback on stock Serviio 2.5
(free DLNA server) for this generation of TVs:

* A renderer profile causing re-encode outputs to use H.264 (capable of
  carrying the frame-packing SEI) rather than MPEG-2 video.
* An ffmpeg wrapper that appends the correct frame-packing parameter
  whenever Serviio re-encodes a 3D-flagged input.
* A lossless bitstream tool that inserts the 16-byte SEI before every IDR
  in existing H.264 files, without re-encoding, for streams that would
  otherwise be remuxed bit-exact.

The fix uses only standard H.264 stereoscopic signalling syntax; no DRM or
copy-protection mechanism (PlayReady, Marlin, CI+) is involved or affected.
All conclusions were verified by single-variable tests on the actual
hardware.
