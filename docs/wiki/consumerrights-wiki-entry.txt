The '''Sony BRAVIA pre-Android Linux TVs''' are the 2011&ndash;2012 generation of Sony Bravia flat-panel televisions, which ran a proprietary Linux-based platform before Sony switched the BRAVIA line to Android TV. Hardware ranged from entry models to flagships with 12-bit X-Reality PRO video processing and active (shutter-glasses) 3D. All models included DLNA media playback and an HTML/JavaScript widget platform (ApplicaCast) served from Sony-operated servers.

==Consumer-impact summary==
The hardware of this generation remains fully functional years after the platform was abandoned &mdash; including 12-bit video processing and active 3D on the higher-end models &mdash; but Sony discontinued every software pillar the sets depend on. Owners are left with: smart functionality that no longer works and cannot be restored, no official firmware recovery path for a failed or factory-reset set, GPL-licensed sources that are no longer obtainable from the copyright distributor, and a 3D playback feature that silently fails over DLNA. The last item is notable because it was never advertised as a service that could end: the panels and 3D hardware work, but the signalling the sets were built to read is never generated by mainstream media servers, so the feature appears broken while the hardware is fine &mdash; and it has been restored entirely through owner reverse engineering.

==Incidents==
This is a list of all consumer-protection incidents related to this product line. Any incidents not mentioned here can be found in the [[:Category:{{PAGENAME}}|{{PAGENAME}} category]].

===Smart services shut down (platform wind-down)===
The ApplicaCast widget platform depended on Sony-operated servers for its content. When those services were wound down, the sets permanently lost their smart functionality. The hardware itself is unaffected, but no official path exists to restore or replace the removed capabilities.

===Firmware downloads removed (January 2022)===
Sony removed the firmware update images for these models from its support site. A set that fails, or is reset to factory defaults, can no longer be brought back to working firmware through official channels &mdash; the only remaining sources are third-party archives of the files Sony once published.<ref name="repo">Owner research repository documenting the platform and its withdrawal: [https://github.com/danielcamposramos/sony-bravia-linux github.com/danielcamposramos/sony-bravia-linux].</ref>

===GPL source releases deleted===
The sets run a Linux kernel and other GPL-licensed components, for which Sony was obligated to make the corresponding source code available. Those source downloads were later removed from Sony's own site; the sets continue to run the binaries, but the source is no longer obtainable from the copyright distributor.<ref name="repo" />

===3D playback silently broken over DLNA===
The 3D-capable models of this line auto-engage 3D from exactly one signal: a ''frame_packing_arrangement'' SEI message (H.264 D.2.4, payload type 45) embedded in the H.264 elementary stream. They ignore the Matroska StereoMode container tag &mdash; the only 3D flag standard rip files carry &mdash; so every DLNA-served 3D video plays flat. The feature was never announced as ending; it fails silently on hardware that displays 3D perfectly from other inputs. An owner reverse-engineered the detection mechanism and restored fully automatic 3D playback on stock Serviio 2.5 (free) using only standard H.264 stereoscopic signalling; no DRM or copy-protection mechanism is involved.<ref name="discussion">Write-up, evidence base and community testing ask: [https://github.com/danielcamposramos/sony-bravia-linux/discussions/1 Discussion #1].</ref><ref name="forum">Serviio forum thread: [https://forum.serviio.org/viewtopic.php?f=7&t=31269 forum.serviio.org].</ref>
